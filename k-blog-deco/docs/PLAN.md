# K 블로그 꾸미기 — 서비스 기획서 (v0.1)

> 레퍼런스(홈페이지·블로그 주소, 화면 캡처, 참고 영상)를 넣고 "이런 스타일로"를 말하면,
> AI 가 네이버 **홈페이지형 블로그**용 스킨 이미지·버튼 위젯·모바일 커버를 만들어 주고,
> 만든 뒤에도 말로·손으로 계속 고칠 수 있는 웹 서비스.

---

## 1. 먼저 알아야 할 제약 — 네이버 블로그는 "꾸미기 API"가 없다

| 항목 | 사실 | 기획에 미치는 영향 |
|---|---|---|
| 스킨·타이틀·위젯 변경 API | 네이버가 공개 API 를 제공하지 않음 | 블로그에 **자동 적용은 불가**. 결과물을 **이미지 + 붙여넣기 코드 + 단계별 가이드**로 제공 |
| 블로그 글쓰기 API | 2020년 광고성 글 문제로 종료 보도 | 글 자동 발행도 기획 범위에서 제외 |
| 네이버 로그인 | 공식 OAuth 2.0 제공 | 회원가입/로그인은 네이버 로그인으로 처리 (요구사항 1) |
| PC 홈페이지형 구성 | 리모콘(스킨배경·타이틀) + 위젯 직접등록(HTML) | 결과물을 이 세 군데에 맞춰 설계 |

**규격 수치** (`src/lib/naver/spec.ts` 한 곳에서 관리 — 네이버 화면이 바뀌면 이 파일만 수정)

- 본문 폭 966px, 타이틀 영역 높이 50~300px
- 위젯 직접등록: 가로 170px 고정, 세로 최대 600px → 버튼 1개 = 위젯 1개, 한 줄 최대 5개
- 스킨 배경(상단 이미지): 넓은 화면 대응을 위해 가로 2000px로 제작
- 모바일 커버: 1080×1080

> ⚠️ 위 수치는 네이버 공식 문서가 아니라 관리 화면·실무 자료 기준입니다. **실제 블로그에 1회 적용해 보고 확정**해야 합니다.

## 2. 사용자 흐름 (요구사항 ↔ 구현)

```
① 네이버 로그인 ─▶ ② 새 디자인 마법사 ─▶ ③ AI 생성 ─▶ ④ 편집기(말/손으로 수정) ─▶ ⑤ 내보내기 ─▶ 네이버에 붙여넣기
```

| 요구사항 | 구현 |
|---|---|
| 1. 네이버로 로그인해서 접속 | `/api/auth/naver/login` → 네이버 인증 → `/callback` 에서 state 검증·프로필 조회 → 서명된 세션 쿠키(30일) |
| 2. 레퍼런스와 유사하게, 사진·내용 반영해 자동 생성 | 마법사에서 **주소 분석**(색·폰트·메뉴·대표 이미지 자동 추출), **캡처 업로드**, **영상 업로드**(브라우저에서 장면 6개 추출), **내 사진**, **스타일 요청 문장**, **버튼 구성** 입력 → AI 가 디자인 JSON 생성 |
| 3. 가장 많이 쓰이는 모델 권장 | Claude Opus 5.5 기본 (근거는 §4). `AI_MODEL` 환경 변수로 교체 가능, 키가 없으면 '템플릿 모드'로도 동작 |
| 4. 모든 기능을 API 로, 생성 후 자유 수정 | 화면도 REST API(`/api/v1`)만 사용 → 외부 연동과 기능이 100% 동일. 개인 API 토큰, OpenAPI 3.1 명세 제공. 수정은 **말로(AI)**, **직접(끌기·속성)**, **버전 되돌리기** 3가지 |

### 화면 구성

| 경로 | 화면 | 주요 기능 |
|---|---|---|
| `/` | 첫 화면 | 서비스 소개, 네이버로 시작하기 |
| `/dashboard` | 내 디자인 | 프로젝트 목록, 새로 만들기, 삭제 |
| `/projects/new` | 마법사 5단계 | 기본 정보 → 레퍼런스 → 스타일 요청(프리셋 8종·분위기·자유 문장·버튼) → 내 사진 → 확인 |
| `/projects/[id]` | 편집기 | PC 미리보기(네이버 화면 시뮬레이션) / 상단 편집(끌어서 이동·크기) / 모바일 커버, 탭: AI 수정·요소·스타일·버튼·버전, 실행 취소, Ctrl+S |

| `/developers` | API 연동 | 개인 API 토큰 발급/삭제, 엔드포인트 목록, OpenAPI |

## 3. 핵심 설계 — "디자인 JSON 하나가 모든 것의 원천"

AI 가 이미지를 직접 그리게 하지 않고, **레이어 구조의 디자인 문서(BlogDesign JSON)** 를 만들게 했습니다.

```
BlogDesign
 ├─ palette (주·보조·포인트·배경·면·글자·보조글자)
 ├─ fonts (제목/본문 — 무료 한글 웹폰트 10종 중)
 ├─ layout (타이틀 높이, 메뉴 바 표시, 버튼 줄 위치)
 ├─ hero    : 아트보드 (966px 칼럼 좌표, 배경은 2000px 로 확장) + 레이어[글자·사진·사각형·원]
 ├─ menu    : 버튼 공통 스타일 + 버튼 목록(이름·보조문구·이모지·링크)
 └─ mobile  : 1080×1080 아트보드 + 레이어
```

이렇게 한 이유:

1. **한글이 깨지지 않음** — 이미지 생성 AI 는 한글 글자를 자주 틀리지만, 여기서는 글자를 실제 폰트로 그립니다.
2. **생성 후 자유 수정** — 레이어 단위라서 글자·색·위치를 사람이 바로 고칠 수 있고, AI 수정도 "JSON 을 고쳐 달라"는 요청이 됩니다.
3. **미리보기 = 결과물** — 같은 Canvas 렌더러(`src/lib/render/canvas.ts`)로 미리보기와 PNG 내보내기를 하므로 보이는 그대로 나옵니다.
4. **안전** — 모든 입력(AI 출력·API 입력·편집기 저장)은 `normalizeDesign()` 을 통과해 범위·색상·링크(http/https 만)·사진 소유권이 보정됩니다.

## 4. AI 설계

### 모델 선택

| 용도 | 기본 모델 | 이유 |
|---|---|---|
| 레퍼런스 분석 + 디자인 생성 | `claude-opus-5-5` | 캡처·영상 장면 **이미지 이해**, 복잡한 **JSON 스키마를 지키는 구조화 출력**, 좌표·여백 같은 레이아웃 추론이 이 서비스의 핵심이라 최상위 모델을 기본값으로 둠 |
| 말로 수정 | 같은 모델 (effort 를 한 단계 낮춤) | 기존 디자인을 유지하면서 요청 부분만 바꾸는 작업 |

- 일반 사용자 인지도는 ChatGPT 가 가장 높지만, 이 서비스에서 AI 가 하는 일은 "이미지 분석 → 정확한 구조의 디자인 JSON" 이므로 그 작업 적합도로 골랐습니다.
- AI 호출은 `src/lib/ai/` 한 곳에만 있어서, 다른 모델·회사로 바꾸거나 **배경 일러스트용 이미지 생성 AI** 를 추가하는 것도 이 폴더만 고치면 됩니다.
- 비용을 줄이고 싶으면 `.env` 에서 `AI_MODEL=claude-sonnet-5-5` 로 바꾸면 됩니다 (품질은 실제 비교 후 결정 권장).

### 호출 방식 (Anthropic 공식 SDK)

- **구조화 출력**: 디자인 스키마(zod)를 JSON 스키마로 보내 형식을 강제 → 파싱 실패 최소화
- **스트리밍 + max_tokens 64000**: 긴 응답에도 타임아웃 없이 수신
- **서버 측 대체 모델(`fallbacks: "default"`)**: 안전 분류기가 요청을 거절하면 Anthropic 이 권장 모델로 자동 재시도
- **시스템 프롬프트 캐시**: 네이버 규격·디자인 원칙(고정 부분)을 캐시해 반복 비용 절감
- **입력 구성**: 요구사항 텍스트 → 레퍼런스별(메모·URL 분석 결과·이미지) → 내 사진(ID·용도·이미지)
- **사용량 기록·한도**: 모든 호출을 `ai_runs` 에 토큰·시간과 함께 기록, 사용자당 시간당 호출 수 제한(`AI_RATE_LIMIT_PER_HOUR`)

### 1회 비용 추정 (참고용, 실측 아님)

| 작업 | 입력 | 출력 | 예상 비용 |
|---|---|---|---|
| 생성 (레퍼런스 이미지 5장 내외) | 약 1.2만 토큰 | 약 1만 토큰 (추론 포함) | 약 $0.25 (≈ 350원) |
| 말로 수정 1회 | 약 0.8만 토큰 | 약 0.8만 토큰 | 약 $0.19 (≈ 270원) |

Opus 5.5 단가($4 / $20 per 1M 토큰) 기준 추정입니다. 실제 키로 10~20건 돌려 `ai_runs` 기록으로 확정한 뒤 요금제를 정하세요.

### 템플릿 모드 (AI 키 없을 때)

업종·키워드로 8개 스타일 프리셋 중 하나를 골라 규칙 기반으로 디자인을 만들고, "제목 크게 / 버튼 둥글게 / 네이비 톤으로" 같은 간단한 수정만 처리합니다. 개발·시연용입니다.

## 5. API 설계

- 기본 경로 `/api/v1`, JSON, 에러 형식 `{ "error": { "code", "message", "details" } }`
- 인증: 웹은 세션 쿠키(+Origin 검사로 CSRF 차단), 외부 연동은 `Authorization: Bearer kbd_...` 개인 토큰 (원문은 발급 시 1회만 표시, DB 에는 해시만 저장)
- 명세: `GET /api/openapi.json` (OpenAPI 3.1, Brief·BlogDesign 스키마 포함)

| 영역 | 엔드포인트 |
|---|---|
| 계정 | `GET /me` |
| 프로젝트 | `GET/POST /projects`, `GET/PATCH/DELETE /projects/{id}` |
| AI | `POST /projects/{id}/generate`, `POST /projects/{id}/revise` |
| 디자인·버전 | `GET/PUT /projects/{id}/design`, `GET /projects/{id}/versions`, `GET /projects/{id}/versions/{vid}`, `POST .../restore` |
| 내보내기 | `GET /projects/{id}/export` (파일 규격·가이드), `POST` (위젯 이미지 → 붙여넣기 코드) |
| 이미지 | `GET/POST /assets`, `PATCH/DELETE /assets/{id}`, 공개 주소 `/files/{key}` |
| 레퍼런스 | `POST /references/inspect` |
| 토큰 | `GET/POST /tokens`, `DELETE /tokens/{id}` |

모든 저장은 **새 버전**으로 남고(덮어쓰기 없음), 되돌리기도 "옛 버전을 새 버전으로 복사"라 기록이 사라지지 않습니다.

## 6. 기술 구성

```
[브라우저]
  Next.js 화면 ── Canvas 렌더러(미리보기·PNG) ── 영상 장면 추출·이미지 축소
       │ fetch (/api/v1 만 사용)
[Next.js 서버 (Node)]
  라우트 핸들러 ─ 인증(세션/토큰) ─ 서비스 계층 ─ normalizeDesign
       ├─ Drizzle ORM ─ SQLite(libSQL)  ※ 운영: Turso 또는 Postgres 로 교체 가능
       ├─ 파일 저장소 ─ 로컬 디스크       ※ 다중 서버: S3/R2 로 교체
       ├─ 레퍼런스 분석기(SSRF 차단)
       └─ Anthropic SDK ─ Claude
[네이버] 로그인(OAuth) 만 연동
```

| 구분 | 선택 |
|---|---|
| 프레임워크 | Next.js 16 (App Router, TypeScript), React 19, Tailwind CSS 4 |
| DB·저장소 | Drizzle ORM + Postgres — 운영은 Supabase(서울 리전, DB + 비공개 Storage 버킷), 로컬은 내장 Postgres(PGlite) |
| 인증 | 네이버 OAuth 직접 구현(외부 인증 라이브러리 의존 없음) + jose(JWT 서명 세션) |
| AI | `@anthropic-ai/sdk` (구조화 출력·스트리밍·대체 모델) |
| 폰트 | Pretendard + Fontsource 한글 폰트 9종 (모두 OFL 무료, npm 자체 호스팅) |
| 배포 | Vercel 별도 프로젝트 → `deco.ko372.com`, ko372.com 도구함에서 연결 (Docker 단일 서버 배포도 지원) |

## 7. 보안 체크

- OAuth `state` 검증, 로그인 후 이동 경로는 내부 경로만 허용(오픈 리다이렉트 차단)
- 세션 쿠키 httpOnly·SameSite=Lax·HTTPS 시 Secure, 상태 변경 요청 Origin 검사
- 모든 데이터는 소유자 확인 후 접근(남의 프로젝트·사진 ID 사용 불가)
- 업로드는 파일 내용(매직 바이트)으로 PNG/JPG/WebP/GIF 만 허용, SVG 차단, 8MB 제한
- 레퍼런스 주소 분석: 사설·루프백·메타데이터 IP 차단, 리다이렉트마다 재검사, 크기·시간 제한
- 버튼 링크는 http/https 만 허용(`javascript:` 등 제거), 위젯 HTML 은 이스케이프 처리
- 운영 환경에서는 개발용 로그인 자동 비활성화, `SESSION_SECRET` 32자 미만이면 기동 실패
